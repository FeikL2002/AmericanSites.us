## HQ implementation review

Reviewed the actual SQLite store, HTTP server, local command CLI, backend tests,
Vite configuration, dashboard data handling, and animation status wiring.
The supported trust boundary is one trusted local operator. CLI actor labels
enforce workflow roles but do not authenticate separate users. HTTP is read-only.
There is no paid model execution adapter, deployment adapter, outreach adapter,
or destructive-action adapter in this slice.

Verified protections:

- Server-owned legal transitions and role checks; transaction-backed revision
  comparisons and command idempotency.
- Implementation digests tied to review/test evidence. A later failed test or
  changes-requested review supersedes an earlier pass for the same digest.
- Expiring worker leases; task completion is not generated by timers.
- Step, attempt, runtime, and task-count limits. Stop actions remain usable
  after step/runtime exhaustion.
- SQLite records and idempotency survive closing and reopening the database.
- HTTP mutation requests are rejected; the API serves only state and health,
  not arbitrary files. Loopback Host and Origin checks reject foreign origins.
- Session token usage and cost remain unavailable, distinct from manually
  recorded provider receipts. No inference that this ChatGPT session is free.

## Findings resolved during review

1. **Evidence gate bypass:** a previous pass could override a later failure.
   Reproduced using an isolated in-memory database; fixed to consult the latest
   matching evidence. Regression tests pass.
2. **Stop unavailable at step limit:** the common limit gate blocked cancellation
   and failure handling. Fixed to retain stop actions.
3. **Malformed HTTP target handling:** unguarded URL parsing could throw from the
   request callback. Parsing is now guarded and returns a bounded error.
4. **Loopback DNS rebinding:** the API now validates Host and Origin. Vite also
   restricts allowed hosts to explicit local hosts before proxying API requests.
5. **Hidden live work:** a newer inactive assignment could hide active work in
   the worker display. Live leases now take priority and duplicate developer
   starts are rejected.
6. **Reviewer lease concurrency:** two pending review handoffs could obtain live
   leases simultaneously for one reviewer. Reproduced in memory; fixed by a
   heartbeat lease check with a regression test.
7. **Historical ownership:** playback previously attributed work to a handoff's
   actor. A deterministic event reducer now follows actual task ownership and
   recorded leases. Missing old heartbeat history remains inactive rather than
   being backfilled. New heartbeats and assignment data are recorded.
8. **Unrelated inspector assignment:** removed the fallback that showed an
   unrelated task for an idle worker. Task-row selection is explicit.
9. **Serving runtime state:** Vite now denies the database, WAL, and runtime data
   directory. Requests for the real database and WAL paths returned 403.
10. **Overlapping polls:** each request now has its own timeout/controller and
    schedules the next request only after finishing, preventing older requests
    from overwriting newer results.

## Deployment and capability limits

The repository's historical website is not verified as the source of the
current hosted AmericanSites deployment. Its original Formspree and Stripe
integrations were read but not submitted or charged. The committed historical
Python virtual environment and ZIP archives are not HQ dependencies.

This review does not approve a public write API or unattended execution. Hosted
write access requires authenticated identities, authorization, a durable worker
runtime, and approvals bound to immutable action/artifact details. Provider
receipt recording is accounting, not a budget-enforcing paid runner. The initial
slice correctly leaves paid execution disabled.
